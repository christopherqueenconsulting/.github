Where LLM features break, and the check that catches it

These three checks run in public repos today. Each number comes with its limits.

A model grades work, and no hard check backs the grade. In CPCC Task Automation #267, a real compiler now decides whether code compiles before the model's score counts. If the compiler cannot run, the result is "cannot verify", never a fail. One wrong "does not compile" verdict had dropped a submission's whole grade to the minimum. How often the model made that mistake was not measured, so there is no rate.

A release waits undeployed, and nobody is told. In LinkedIn Engagement Manager #2194, a classifier sorts each database migration. Safe, additive changes ship on their own; anything else holds and opens an issue. An hourly check alerts when a release has waited more than 3 hours. Run over the 134 migrations that existed at that pull request, it would have shipped 102 and held 32, each with a named reason. The classifier has 68 tests.

A scheduled job runs green and produces nothing. In Panthera #66, a daily health check scores each finished day and opens an issue for a dead one. It flags a dead day the next morning, about 26 hours later at the earliest. Its threshold was set on past data, not held out.

Sources and fuller caveats for all three: the project write-ups.
